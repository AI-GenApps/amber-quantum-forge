# 03 — POST /api/chat/sync Endpoint

## Goal

Create a `POST /api/chat/sync` endpoint that accepts a batch of client-side chat messages and upserts them into a `chat_messages` DB table. This gives the server a copy of chat history for analytics, and provides a backup if the client loses local storage.

Chat history is **client-owned** in v1 (SwiftData / AsyncStorage is the primary store). The sync is periodic and best-effort — not real-time.

## Context

### DB table needed: `chat_messages`

Add to `packages/db/src/schema.ts`:

```sql
CREATE TABLE chat_messages (
  id           SERIAL PRIMARY KEY,
  client_id    TEXT NOT NULL,        -- client-generated UUID, unique per message
  user_id      INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  role         TEXT NOT NULL,        -- "user" | "assistant"
  content      TEXT NOT NULL,
  created_at_client TIMESTAMP NOT NULL,  -- timestamp from client (when message was created on device)
  synced_at    TIMESTAMP NOT NULL DEFAULT now(),
  UNIQUE (client_id, user_id)
);
```

`client_id` is a UUID generated by the client. Using `(client_id, user_id)` as unique key prevents duplicate syncs.

### Request

```json
POST /api/chat/sync
Authorization: Bearer <apiJwt>
Content-Type: application/json

{
  "messages": [
    {
      "clientId": "uuid-v4-from-device",
      "role": "user",
      "content": "Hello",
      "createdAt": "2024-01-15T10:30:00.000Z"
    },
    {
      "clientId": "uuid-v4-from-device-2",
      "role": "assistant",
      "content": "Hi! How can I help?",
      "createdAt": "2024-01-15T10:30:01.500Z"
    }
  ]
}
```

### Response

```json
{
  "synced": 2,
  "skipped": 0
}
```

`synced`: number of new messages inserted.
`skipped`: number of messages that already existed (duplicate `clientId`).

### Upsert strategy

Use Drizzle's `onConflictDoNothing()` — if a `(clientId, userId)` already exists, skip it silently. Count affected rows to compute `synced` vs `skipped`.

### Validation

- Max 100 messages per sync request (prevent abuse).
- `clientId` must be non-empty string.
- `role` must be `"user"` or `"assistant"`.
- `content` must be non-empty, max 10,000 chars.
- `createdAt` must be a valid ISO 8601 date string.

### Route placement

Add to `packages/api/src/routes/ai.ts` as `POST /sync` (mounted at `/ai`, so full path is `/api/ai/sync`). Or create a separate `chat.ts` route file. Choose `ai.ts` for simplicity in v1 — all AI/chat routes in one file.
