# Vehicle physics core: Rapier raycast vehicle, fixed step, determinism

## Goal

Build a headless, deterministic driving simulation in `@city-drive/core`.
A car driven by scripted inputs on a flat world must behave like a car
(accelerate, brake, steer, reverse, handbrake drift) and replay
bit-identically.

## Context / Decisions

- **Rapier:** use `@dimforge/rapier3d-compat`. Its compat build inlines the
  wasm, so `await RAPIER.init()` works under Vitest. Use
  `world.createVehicleController(chassis)` with `addWheel`, per-wheel
  suspension, `setWheelEngineForce`, `setWheelBrake`, `setWheelSteering`, and
  `updateVehicle(dt)`. Read the official guide first:
  https://rapier.rs/docs/user_guides/javascript/vehicle_controller
- **Fixed step** `1/60` s with an accumulator in a `SimClock` (pure). The
  render loop (task 07) only interpolates. Never read wall-clock time inside
  the simulation.
- **Determinism:**
  - Avoid platform `Math.sin`/`Math.cos` in simulation code where they affect
    state (use Rapier's own rotation APIs or a small deterministic
    approximation).
  - Snapshot state with `world.takeSnapshot()`.
  - Produce a stable hash of the car state (position/rotation/velocity rounded
    to 1e-4) for tests.
- **API shape** (suggested; keep files under ~250 lines each):
  - `createPhysicsWorld(): Promise<PhysicsWorld>`
  - `addStaticBox(...)` and `addGround(...)`
  - `createCar(world, spec: CarSpec): Car`
  - `Car.applyInput({ throttle: -1..1, steer: -1..1, handbrake: boolean })`
  - `world.step()`
  - `Car.state(): { position, rotation, speedKmh, wheelContacts }`
- **`CarSpec` data** (mass, engine force, brake force, max steer angle,
  suspension stiffness/damping, friction slip, wheel radius/positions) lives
  in `src/cars/specs.ts`. Task 12 adds a roster; define 1 baseline car now.
- **Tuning target** ("arcade, forgiving"): 0–60 km/h in about 3–4 s; top
  speed about 110 km/h; the car stays upright under full steer at top speed;
  a handbrake turn produces yaw without flipping. Encode these as tests with
  tolerance bands.
- **Reset:** add `Car.respawn(pose)` for when the car flips or is stuck (task 07
  wires the UI).

## Dry-run amendments (2026-10-15)

These come from the read-only dry-run review of this epic. **Where they conflict with anything above, these amendments win.**

- **Snapshot test:** Rapier's `takeSnapshot()` / `restoreSnapshot()` restore only the physics world. Vehicle controllers live JS-side and are **not** restored. The test must:
  1. restore the world
  2. rebuild the controller from the `CarSpec`
  3. re-apply the per-wheel inputs
  4. compare hashes that **exclude** visual wheel rotation

  If exact equality is unattainable, fall back to a documented tolerance of 1e-3 and record why.
- **No-tunnelling test:** enable CCD on the chassis.
- **Extend `Car.state()` now**, because later tasks consume these fields:
  - `velocity`, `yawRate`, `longitudinalG`, `lateralG` (taxi comfort, task 10)
  - per-wheel `slip` (skid audio, task 14)
  - a drained list of collision impulses, from an `EventQueue` owned by `PhysicsWorld` and exposed for tasks 09 and 10
- **Parameterize** the handling sanity suite with a `CarSpec` argument; task 12 reuses it over 6 cars.
- **Fixtures:** the determinism fixture is generated only by `tool/gen-determinism-fixture.ts`, and lives in `test/fixtures/`, which Biome excludes.
- **Files Touched:** add `.agents/resources/2026-10-15/city-drive-qa/03/README.md` (tuning values and timings).
