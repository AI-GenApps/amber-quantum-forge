# Pocket Biome — art-direction dry run

Three original art directions for Pocket Biome, each rendered as 3 species ×
3 growth stages, a habitat background, a UI chip sample, and a composited
1080×2400 habitat mockup. Purpose: let the user pick a direction (and price
the full 30-species set) before any final art is produced. No final art,
no app integration, and no gameplay changes are in this task.

**IMPORTANT — provenance note (read first):** this dry run's images were
generated by an earlier agent run that produced all 33 source images and
then stopped (hit a usage limit) before writing this README. The exact
per-image prompt text sent to `image-gen` for each file was **not saved
anywhere and is now lost** — there is no log of the literal prompts. This
agent (the one finishing the task) only had the finished PNGs, the
directory/file naming, and the tool/model metadata below to work from. The
"direction brief" for each style further down is **reconstructed from
looking at the generated images themselves**, not a transcript of what was
asked for. Treat those briefs as an honest description of what was
delivered, not as the original prompt record.

## What this agent did on top of the existing images

1. Viewed every one of the 33 source PNGs individually.
2. Verified alpha with Pillow (mode/size table below; all sprite and chip
   files are RGBA, all three habitat backgrounds are RGB by design).
3. Probed pixel values directly (not just a visual look) and found genuine
   **premultiplied-color contamination**: pixels with `alpha == 0` that
   still carried arbitrary leftover RGB (for example a pure
   `(255, 255, 0)` yellow baked into a fully-transparent pixel on
   `direction-a-glass-terrarium/mossling-seed.png`). This is invisible in a
   flat 1:1 view over a checkerboard, but bilinear/mipmap scaling (exactly
   what a game engine does when it draws a sprite smaller than its source
   texture) can blend that hidden color into the visible edge, producing a
   colored fringe.
4. Fixed it with an alpha-weighted edge-color decontamination pass
   (blur the premultiplied color and the alpha weight, divide, and use the
   result to replace the RGB of every non-fully-opaque pixel; fully-opaque
   core pixels are left untouched). This was applied **in place** to **all
   30 RGBA files** (27 sprites + 3 UI chips; the 3 RGB habitat backgrounds
   have no alpha channel and were left untouched). "Cleaned" below means
   this pass ran on the file; "notable" means the file measured meaningful
   stray color in its transparent margin before cleaning (i.e. the fix
   plausibly changed its rendered edge, not just a no-op safety pass).
5. Separately, several sprites — most visibly in Direction A
   (`sunbud-bloom`, `tidebell-bloom`, `mossling-bloom`) and a few in
   Direction B — show a soft warm/glow **halo baked into genuinely
   semi-transparent gradient pixels** (a rim-light/bloom effect the source
   generation painted into the alpha gradient itself, with smoothly
   varying, locally-consistent color, not a randomly-wrong fringe). That
   halo is a **stylistic characteristic of the generation**, not a matting
   defect, and erasing it would mean repainting the art, which is out of
   scope for a de-fringe pass — it was left as-is and is called out per
   direction below so the user can judge it as part of the style, not miss
   it as a defect.

## Mockup construction

Each `mockup-*.png` is a Pillow composite (`RGB`, 1080×2400) built from that
direction's own assets, not a generated image:

- Header: "TINY HABITAT" eyebrow, "Pocket Biome" title, and the subtitle
  "Grow a tiny world, one careful harvest at a time." — these match the
  real strings in `apps-native/games/pocket_biome/lib/src/pocket_biome_ui.dart`
  (read for reference only; not modified).
- Stats row: ALBUM / COMPOST / POTS, restyled as three cards, each holding
  the direction's own `ui-chip.png` next to a label (Quicksand, bold) and a
  value (Fraunces, bold, SOFT-axis). Sample values (3 / 12 / 6) are
  illustrative, matching the real widget's field names.
- Terrarium panel: the direction's `habitat-background.png`, rounded and
  drop-shadowed, with 6 sprites placed across the pot grid at mixed growth
  stages — mossling-seed, sunbud-sprout, tidebell-bloom (row 1) and
  mossling-bloom, sunbud-seed, tidebell-sprout (row 2) — so all three
  species and all three stages are visible in every mockup.
- Primary action button: a pill button reading "Plant Mossling" (the real
  primary action's label in `pocket_biome_controls.dart`), set in Fraunces.
- Fonts: **Fraunces** (`fonts/fraunces/Fraunces[SOFT,WONK,opsz,wght].ttf`)
  for the title, stat values, and button label, and **Quicksand**
  (`fonts/quicksand/Quicksand[wght].ttf`) for the eyebrow, subtitle, and
  stat labels — the same files shipped for task
  `16-games-portfolio-wave2/03`. Pillow **does** support the variable
  Fraunces SOFT axis on this box (`ImageFont.set_variation_by_axes`,
  confirmed via `get_variation_axes()` → `Softness` 0–100); the mockups use
  a high softness value (~90–100) for the friendly display look.
- Sprite-to-pot alignment is a hand-tuned approximate grid (not
  pixel-detected from each background's painted circles), since the three
  backgrounds' painted pot positions differ slightly and this is a dry run,
  not final layout. It reads as a real 2×3 pot grid in all three mockups;
  it is not meant to be pixel-perfect against the final habitat art.

## Direction briefs (reconstructed from the images, not original prompts)

### A — Glass Terrarium

Soft 3D render, glossy spherical glass jar with a turned-wood lid, warm
golden-hour light, pebble/soil strata visible through the glass, plush
moss/vinyl-look creatures with big glossy eyes (mossling, sunbud) and a
jewel-toned glass-textured tidebell. Strong rim lighting and a warm
backlight bloom around several sprites (mossling-bloom, sunbud-bloom,
sunbud-seed, tidebell-bloom) — this is a deliberate glow in the alpha
gradient, not a fringe defect; it reads as "premium collectible in a
lightbox."

**Pros:** highest perceived production value; strongest "collectible"
appeal; the glass-jar habitat background is the most polished of the three
and would read well on a store listing.
**Cons:** most expensive style to keep consistent across 30 species ×
3–4 stages (glossy specular highlights and rim light are easy to get
subtly wrong per-asset); the warm backlight glow needs a consistent
light-direction rule across every future asset or the set will look
mismatched; heaviest render, so likely the highest rework rate.

### B — Storybook Watercolor

Hand-painted watercolor/gouache look, visible paper grain and pigment
bleed, muted natural palette, a cork-stoppered mason jar habitat, delicate
cute-but-not-toy character faces (closed/sleepy eyes on seed and bloom
stages, alert eyes on sprout). Some sprites (mossling-bloom,
mossling-seed, sunbud-bloom) carry a soft warm-green painterly glow behind
the subject, consistent with a backlit-paper aesthetic.

**Pros:** most distinctive/least generic among mobile idle-garden games;
watercolor texture forgives minor per-asset inconsistency (unlike glossy
3D, brush variance reads as "hand painted," not "off-model"); works well
at small icon sizes because the silhouette carries the read.
**Cons:** flattest of the three in a UI context (less pop against a light
background than A or C); paper-grain texture increases per-file size
slightly; harder to keep a consistent light source across 30 species since
watercolor "backlight" is a manual painterly choice per piece, not a
render parameter.

### C — Chunky Toy

Saturated, flat-shaded vinyl/clay toy look, thick rounded silhouettes, big
simple faces, no visible painterly texture or lighting model beyond basic
toy-plastic specular highlights. Cleanest alpha edges of the three
directions — visually and by the contamination measurements above, this
direction had the least stray edge color to begin with.

**Pros:** cheapest to scale to 30 species consistently (flat shading has
far fewer places for a per-asset generation to drift off-model than A's
glossy render or B's painterly bleed); reads clearly at small sizes;
matches the "toy shelf" positioning that's easy to merchandise (stickers,
plush, etc. later); technically the cleanest source files.
**Cons:** least differentiated — this is the most common style among
existing casual/idle mobile games (closest to "generic cute mobile
mascot"); habitat background reads slightly more toylike/less atmospheric
than A or B, which may undersell the "biome" fantasy the audit called out
as the product's core appeal.

## Cost sheet (30-species target)

Assumptions: 30 species × **3–4** growth stages (seed/sprout/bloom, some
species may need a 4th "wilt/dormant" stage per `economy.md`), plus shared
UI and background assets. This dry run generated 3 species × 3 stages = 9
sprites per direction; scaling to the full roster is a straight
multiplication, not a new pipeline.

| Item | Count (30-species target) | Notes |
| --- | --- | --- |
| Species growth-stage sprites | 90–120 | 30 species × 3–4 stages |
| Behaviour/animation variants | ~6 per species → up to 180 | task calls out "6 behaviours"; only needed if final direction uses per-behaviour art rather than code-driven animation of static sprites |
| UI chips / icons | ~6–10 | stat chips, buttons, badges, one style pass |
| Habitat backgrounds | 1–3 | base habitat + optional variants (season/unlock) |
| **Total asset count (low/high)** | **~97 – ~313** | wide range driven mainly by whether behaviours need unique art vs. code-driven animation of the base sprites |

Estimated generations, assuming this dry run's observed **~70 s/image**
and accounting for rework:

| Direction | Rework rate (est.) | Generations for 90 sprites (low case, no behaviour art) | Generations for 300 assets (high case, with behaviour art) | Wall-clock @ ~70s/image (low case) |
| --- | --- | --- | --- | --- |
| A — Glass Terrarium | ~35–40% (glossy render + rim light is easy to get subtly wrong) | ~125–130 | ~410–420 | ~2.4–2.5 h |
| B — Storybook Watercolor | ~30% (painterly variance is more forgiving, but keeping the palette/backlight consistent needs retries) | ~115–120 | ~390 | ~2.2–2.3 h |
| C — Chunky Toy | ~20–25% (flat shading is the most consistent to reproduce) | ~110–115 | ~370–375 | ~2.1–2.2 h |

These are estimates for planning purposes only, based on this dry run's
sample size (9 sprites/direction) and observed pace; actual rework will
depend on how strictly each direction's style guide is written before the
final pass.

## Recommendation

All three directions are viable; none failed the alpha/contact-sheet
checks. Ranked for this product (idle "grow and collect" biome game, where
the audit named the art as the product):

1. **Direction B (Storybook Watercolor)** — most distinctive positioning
   in a genre otherwise dominated by glossy-3D or flat-toy mascots (see
   Terrarium: Garden Idle / Pocket Frogs / Viridi references), most
   forgiving of the natural quality variance across 30 species, and its
   flatter contrast is fixable with UI chrome (the mockup already shows it
   reads fine against a warm paper background).
2. **Direction A (Glass Terrarium)** — the highest ceiling for a store
   listing "wow" screenshot, but the most expensive to keep consistent at
   volume and the direction most likely to need a strict lighting/rim-light
   style guide before the final batch to avoid mismatched assets.
3. **Direction C (Chunky Toy)** — the safest, cheapest, and technically
   cleanest to scale, but the least differentiated; a reasonable fallback
   if budget or timeline is the binding constraint rather than
   differentiation.

This is this agent's recommendation for the write-up only — the actual
pick is a human decision, logged as an open question below.
