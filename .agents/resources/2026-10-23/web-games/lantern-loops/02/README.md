## Seed scheme

- Campaign seed of a puzzle: `FNV-1a(UTF-16 text "ll-gen-1|<puzzle id>")`, a 32-bit unsigned integer,
  stored in each record (`seed`).
- Attempt `k` of a puzzle uses `FNV-1a("<seed>:<k>")` as its PRNG seed (mulberry32). The generator tries
  up to 120 attempts and keeps the first board that meets the anchor-share goal and the band rating
  range of the puzzle; every shipped puzzle met both.
- The PRNG, hash and every other step use integer arithmetic only, so the output is identical on every
  machine. `test/architecture.test.ts` forbids `Math.random`, clocks and `new Date` in `src`.

## What the report holds

`campaign-report.json`: one row per puzzle with `id`, `size`, `rating`, `lanterns`, `stones`,
`mirrors`, `gates`, `colours`, `anchors`, `solutionTiles`, `anchorShare` (percent, one decimal) and
`nodes` (solver guesses to prove uniqueness). It is rebuilt from the stored puzzle codes, not from
generator state, and `test/campaign.test.ts` plus `--verify` fail when it is stale.
