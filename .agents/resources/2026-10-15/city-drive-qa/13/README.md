## Pre-existing build failure (fixed, small necessary change)

`bun run city-drive:build` already failed at HEAD (3282e09, task 12): the core build uses
`tsconfig.build.json` with `types: []`, and `apps-games/city-drive-core/src/save/scheduler.ts` called the
global `setTimeout` / `clearTimeout`, so `tsc` reported `TS2304: Cannot find name 'setTimeout'` (twice).
Proven on a throwaway HEAD worktree (`tsc -p .../tsconfig.build.json` printed the same two errors with no
change of mine in core). Because the build command is part of this task's verification, `scheduler.ts` now
names the two host timer functions in a local interface and reads them from `globalThis` at call time (same
behaviour, fake timers still work, no DOM or Node types). Core tests still pass.

## What was found while testing: the Trail SUV crashed the game

The garage test builds a car visual for every roster car. `car-suv.glb` has a fifth wheel node
(`wheel-back`, the spare on the rear door), and `buildCarParts` threw `expected 4 wheel nodes, found 5`.
That would have crashed the game for any player who bought and selected the SUV (task 12 added it to
the roster, and nothing had built its visual). `src/render/carModel.ts` now treats only
`wheel-(front|back)-(left|right)` as driven wheels and merges any other `wheel-*` node into the body.
Regression test: `test/render/garage.test.ts` ("builds every roster model").
